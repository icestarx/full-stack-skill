# Requirements Document Template

```markdown
# Requirements — [Project Name]

## 1. Background & Goals
- Why this exists (problem statement)
- Expected business outcomes

## 2. Target Users
- User personas (1-3)
- Usage scenarios

## 3. Feature Scope
### P0 — Must Have (product unusable without these)
| ID | Feature | User Story | Acceptance Criteria | Priority |
|----|---------|------------|---------------------|----------|

### P1 — Should Have (significantly improves experience)
### P2 — Nice to Have (icing on the cake)

## 4. Non-Functional Requirements
- Performance requirements (response time / concurrency)
- Security requirements (auth / authorization / data encryption)
- Compatibility (browsers / devices / screen sizes)
- Accessibility requirements

## 5. Acceptance Criteria
- Definition of Done for each P0 feature

## 6. Success Metrics
- What data measures success (conversion rate / DAU / NPS / retention...)

## 7. Explicitly Out of Scope
- Scope boundaries (prevents scope creep)

## 8. Risks & Assumptions
- Key assumptions and validation methods
- Known risks and mitigation plans
```
